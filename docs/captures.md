# Fixture captures

Every capture in `captures/` is generated by `scripts/make-captures.ts`. The protocols are
synthetic and specified here, which is what makes the test suite meaningful: every assertion
compares an inference against a documented layout instead of another inference.

Regenerate with `npm run captures`. Output is deterministic — same bytes on every run.

---

## `binary-session.pcap` / `.pcapng`

TCP, `10.0.0.10:41000` → `10.0.0.20:7401`. Eight request/response rounds, plus a ping/pong and
an error exchange. Both directions carry 10 messages.

```
offset  size  field
0       2     magic      0xa5 0x5a
2       1     length     total message length, big endian, checksum included
3       2     sequence   little endian, +1 per message per direction
5       1     type       0x01 ping, 0x02 pong, 0x10 read, 0x11 data, 0x20 error
6       n     payload    ASCII, e.g. "temperature=21.75"
6+n     2     checksum   crc16/modbus over bytes [0, 6+n), little endian
```

Messages are split across TCP segments, with one out-of-order segment pair and one
retransmission per exchange. The `.pcapng` file is the same traffic in a different container,
so the test suite can assert both parsers produce identical streams.

Expected inference: length-prefix at offset 2 with bias 0, six fields, checksum
`crc16/modbus` matching 10/10.

## `binary-session-v2.pcap`

The same protocol with the type byte removed:

```
offset  size  field
0       2     magic
2       1     length
3       2     sequence
5       n     payload
5+n     2     checksum
```

Its purpose is `protopath diff`: the type byte's disappearance has to show up as a layout change,
not as a silent reinterpretation. The honest answer here is that bytes 5..8 become `text`,
because the payload of this session is ASCII — the tool cannot know a field was removed, only
that the layout moved.

## `text-session.pcap`

TCP, `10.0.0.10:43000` → `10.0.0.20:7402`. Eight line-command exchanges:

```
PING / PONG
GET temp / DATA 23.5
SET led on / ACK 0
GET uptime / DATA 40213
SET mode auto / ACK 0
GET serial / DATA SN-0042
GET bogus / ERR unknown key
PING / PONG
```

Framing is a single-byte terminator `0x0a`. Field inference collapses to one `text` field, which
is the correct answer for a text protocol: the structure is in the words, not in byte offsets.
Labels come from the first word (`verb=GET`).

## `sensor-udp.pcap`

UDP, `10.0.0.30:50000` → `10.0.0.40:7403`. Twenty-four 12-byte datagrams, one direction only.

```
offset  size  field
0       2     origin      0xaa 0x55
2       1     state       0x10 or 0x11
3       1     sequence    +1 per datagram
4       2     temperature big endian, signed, centi-degrees
6       2     humidity    big endian
8       1     node id     3
9       3     reserved    zero padding
```

Framing is recovered as a start-marker `0xaa55`. This fixture exists to prove the UDP path: no
session, no sequence numbers, datagrams simply concatenated in arrival order — which is exactly
why the sequence counter is worth detecting.

Expected inference: start-marker `0xaa55`, `magic`, `type` at the state byte, `payload` for the
rest. `reserved` padding is what stops the header from extending further.

## Ground truth table

| Capture | Framing | Messages | Checksum | Special property |
|---|---|---|---|---|
| binary-session.pcap | length-prefix, 1B BE @2, bias 0 | 10 + 10 | crc16/modbus 10/10 | out-of-order + retransmit |
| binary-session.pcapng | same | same | same | pcapng container |
| binary-session-v2.pcap | length-prefix, 1B BE @2, bias 0 | 8 + 8 | crc16/modbus 8/8 | type byte removed |
| text-session.pcap | delimiter `0x0a` | 8 + 8 | none | ASCII protocol |
| sensor-udp.pcap | start-marker `0xaa55` | 24 | none | UDP, no session |

These numbers are asserted in `tests/`. If a change to the inference changes them, the test
fails before the README can go stale.
